## 0. これは何か

### ヨージの希望（2026-11-02）

> オトモンもいずれは進化したり、共に成長したことによる何かの変化を取り入れていきたい

### 決まったこと（ヨージ決定 2026-11-02：案C）

**二段構えにする。**

```
 ┌───────────────────────────────────────────────────────────┐
 │ ① 共成長の刻印（全100体）                                  │
 │    その子と一緒に集中した時間・ジャンル・渡った大陸に応じて   │
 │    二つ名・光の縁取り（オーラ）・セリフが増える。新しい絵は要らない │
 ├───────────────────────────────────────────────────────────┤
 │ ② 進化（ぬし8体だけ）                                       │
 │    大陸を一緒に渡った「ぬし」が、新しい姿に変わる               │
 │    絵ができた子から順に解禁する（絵がない子は①のオーラのみ）     │
 └───────────────────────────────────────────────────────────┘
```

検討した3案（記録）:

| 案 | 中身 | 採否 |
|---|---|---|
| A 共成長の刻印 | 絵は変えない。二つ名・オーラ・セリフ | ①として採用 |
| B 姿が変わる進化 | 全員に新しい絵。100枚以上要る | 重いので、ぬし8体に絞って②として採用 |
| C 組み合わせ | A を全員、B をぬしだけ | **採用** |

### 調べて分かったこと（2026-11-02・コードより）

- オトモン1体ごとの記録は `gq_otomon.discovered[id]`（`scripts/otomon.js` の `makeRecord()`）:
  `firstMetAt / lastSeen / totalMins / metDays / bond / count`
- **`totalMins` はお供にして集中した分しか増えない**（`grantSessionBond()`、上限なし）＝努力の証として最も正直
- `bond` は毎日のふれあい（`touchActiveOtomon()`）でも上がる＝アプリを開くだけでも上がる。**進化の条件の主役にはしない**
- 絵は1体につき1枚（`image.{large,medium,small}`）。表示は `otomonFace(o, size)` の1か所
- 🌈にじいろの雫（`rainbow_drop`）は `special:'evolve'` が付いているが、進化の効果は未実装（伏線）。
  入手は今のところ連続30日（2個）・100日（1個）のバッジだけ（`otomon.js` の節目報酬表）
- セッション完了時は `Otomon.onSessionComplete(mins)`（`timer.js:423`）。その時のジャンルは `gq_current_genre`（`core.js:426`）
- ジャンルには `color` がある（`settings-genre.js`）→ オーラの色に使える
- ぬし（大陸の旅 §0）: 1=みならいフェニックス(`minaraifenikkusu` SR) … 8=幸福フェニックス(`kouhukufenikkusu` SSR)

### 守るべき判断基準（GQの正典。迷ったらここへ戻る）

1. **本当の努力を要求するか** … 刻印も進化も「その子と一緒に集中した時間」と「大陸の踏破」が条件。ふれあい・リボンだけでは進まない
2. **STARTまでの秒数を伸ばさないか** … ホーム画面・起動時には何も足さない。進化の演出は図鑑で自分から開いたときだけ
3. **集中直後の余韻を奪わないか** … 集中を終えた直後に大きな演出を出さない。刻印は小さな知らせ、進化は図鑑に🌈が付くだけ
4. **サボった人を責めないか** … 刻印も進化も減らない・戻らない。お供を替えても記録は残る。「あと◯時間で…」と急かす文言を出さない
5. **努力の記録を消さない** … 既存の保存データは書き換えない。進化しても前の姿は図鑑で見られる

### やらないこと（スコープ境界）

- ぬし以外の進化（新しい絵が要る。§9 将来）
- 進化による能力差（ナッジやアイテム効果が強くなる等）。見た目と言葉だけ変える
- 刻印・二つ名・セリフの**文章を書くこと**（枠と仮名だけ用意。文言はヨージ／チャッピー）
- 進化後の絵を作ること（ChatGPT 側で作る。§4.4）

## 1. 全体の流れ

```
 集中を終える ──► その子の totalMins・ジャンル別の分が増える
                      │
                      ├─ 刻印の段階を超えた？ ─► 小さな知らせ（ホームには出さない）
                      │                         図鑑の詳細に二つ名・オーラ
                      │
 大陸のゴールを踏む ──► お供の子に「一緒に渡った大陸」を記録
                      │
                      └─ ぬしで、進化の条件を満たした？
                              ─► 図鑑のその子に 🌈 が付く（それだけ）
                              ─► ヨージが図鑑で開いて「進化させる」を押す
                              ─► 進化の演出 → 新しい姿（前の姿も見られる）
```

## 2. データ

### 2.1 新しいキーは作らない。`gq_otomon.discovered[id]` に足すだけ

```js
// makeRecord() と normalizeDiscovered() に足す項目（すべて「足すだけ」。既存の値は触らない）
{
  // …既存: firstMetAt, lastSeen, totalMins, metDays, bond, count
  genreMins:  {},   // { [genreId]: 分 }  お供中に集中したジャンル別の分（リリース後から数える）
  stagesWith: [],   // ['stage1', …]    この子がお供のときに踏破した大陸ID
  markSeen:   0,    // 知らせ済みの刻印の段階（二重に知らせないため。段階そのものは毎回計算する）
  form:       1,    // 姿の段階（1=今の姿 / 2=進化後）。ぬし以外は常に 1
  evolvedAt:  null, // 進化した日時
  showForm:   null, // 図鑑・お供で見せる姿（null=最新の姿）。前の姿を選び直せる
}
```

- `OTOMON_SCHEMA_VERSION` を 3 → 4 に上げ、`normalizeDiscovered()` の `ver < 4` で上の項目を**無ければ足す**
- `gq_otomon` はバックアップ（`exportAllData()`）に既に入っている → 追加作業なし
- `docs/architecture_review.md` §6 の台帳の `gq_otomon` 欄に、足した項目を追記する
- 既存の `totalMins` はジャンル別に分けられない → **過去の分は genreMins に入れない**（推測で埋めない）。
  オーラの色は「genreMins が空ならその子の属性の色」で代用する（§3.2）

### 2.2 刻印は「保存」せず「計算」する

刻印の段階は `totalMins` と `stagesWith` から毎回求める（記録が欠けても自分で直る。大陸の旅 §2.3 と同じ考え）。
保存するのは「どこまで知らせたか」（`markSeen`）だけ。

## 3. ① 共成長の刻印（全100体）

### 3.1 刻印の段階（仮の値。§10 で決める）

| 段階 | 条件（この子と一緒に） | 変わるもの |
|---|---|---|
| 0 | — | いまのまま |
| 1 | 集中 5時間 | 二つ名①・うっすらオーラ |
| 2 | 集中 20時間（≒大陸1つ分）**または** 大陸を1つ一緒に踏破 | 二つ名②・オーラが濃く |
| 3 | 集中 50時間 | 二つ名③・セリフ追加 |
| 4 | 集中 100時間 かつ 大陸を2つ一緒に踏破 | 二つ名④・オーラにきらめき |

- 条件は `totalMins` と `stagesWith` のみ。**bond は使わない**（基準1）
- 数字は大陸の旅の実測（1周＝集中約20〜25時間）に合わせた仮案

### 3.2 オーラ（新しい絵を使わない見た目の変化）

- `otomonFace()` の外側に枠を1つかぶせ、CSS の光の縁取り（box-shadow / drop-shadow）で出す
- 色 = その子の `genreMins` で一番多いジャンルの `color`。空なら属性ごとの既定色
- 濃さ・きらめきは段階で変える
- 出す場所: 図鑑の詳細・お供カード・ヘッダー下の挨拶（**未決 §10-3**）

### 3.3 二つ名とセリフ

- 二つ名 = 「{ジャンル由来の言葉}の{段階の言葉}」のような組み立て式を想定（例: 仮「静けさを知る 相棒」）。**文言は未定**
- セリフは既存の bond 段階セリフと別枠で、刻印段階ごとに1行。100体×4は重いので、まず共通文（属性別）で始める（未決 §10-4）

### 3.4 知らせ方

- 集中を終えた時に段階を超えたら、`markSeen` を更新し、**小さな知らせ**を1回だけ出す（既存の bond 昇格モーダルより控えめ）
- bond 昇格と同時に起きたら、bond 昇格を優先し刻印は図鑑の印だけにする（演出を重ねない。基準3）

## 4. ② 進化（ぬし8体だけ）

### 4.1 進化できる子の定義

`OTOMON_MASTER` のぬしの定義に `evolution` を足す。**`evolution` が無い子は進化しない**（＝絵ができた子から解禁）。

```js
evolution: {
  name:  '（進化後の名前）',
  image: { large:'assets/otomon/<id>/evo/1024/…webp', medium:'…/256/…', small:'…/64/…' },
  line:  '（進化したときの一言）',
}
```

### 4.2 進化の条件（仮。§10-1 で決める）

```
 その子を持っている
   ＋ その子がお供のときに、大陸を1つ以上一緒に踏破した（stagesWith が1件以上）
   ＋ 刻印の段階 2 以上
   ＋ 🌈にじいろの雫を1つ使う（いつ進化させるかは自分で決める）
```

- 雫は今3個しか手に入らない（30日・100日の連続バッジ）。ぬしは8体 → **足りない**。§10-2 で決める

### 4.3 進化の手順（画面）

1. 条件を満たすと、図鑑のその子のセルに 🌈 が付く（ホーム・集中直後には出さない）
2. 詳細を開くと「進化させる」ボタン（雫の所持数も表示）
3. 押すと確認 → 演出（既存の bond 昇格モーダルの流用を想定）→ `form:2`・`evolvedAt` を保存
4. 詳細で「前の姿／いまの姿」を切り替えられる（`showForm`）

### 4.4 絵

- 置き場所: `assets/otomon/<id>/evo/{1024,256,64}/<id>_evo_{1024,256,64}.webp`（既存の命名に合わせる）
- 原画は ChatGPT で作る。8枚そろうまで待たず、できた子から `evolution` を足して解禁
- 絵の読み込みに失敗したら、今の姿＋オーラで表示する（`otomonFace()` の onerror と同じ考え）

## 6. 受け入れ基準（骨組み。§10 確定後に詰める）

- [ ] 既存ユーザーのデータを読み込んでも、既存の項目（totalMins・bond 等）が1つも変わらない
- [ ] お供にして集中すると、その子の `genreMins[今のジャンル]` が増える。お供でない子は増えない
- [ ] 刻印の段階を超えたとき、知らせが1回だけ出る。リロードしても二度出ない
- [ ] ホーム画面・起動時・集中を終えた直後に、進化の演出が出ない
- [ ] 進化できるぬしに 🌈 が付き、図鑑から進化できる。進化後も前の姿を見られる
- [ ] `evolution` の無い子・ぬし以外は進化できない
- [ ] バックアップ→復元で、刻印・進化の状態が保たれる
- [ ] `python3 tools/check_load_order.py` が通る
