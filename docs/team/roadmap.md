## 0. 4人が別々の入口から辿り着いた、ひとつの診断

4人は互いのレポートを見ていません。それでも結論が重なりました。

```text
ミナ（UI/UX）
  「主役のSTARTボタンが、初回起動時に画面1枚分（約965px）下にある」

カイ（批判役）
  「新機能を足す唯一の基準は『STARTを押すまでの秒数が伸びないこと』。
    ホーム7枚のうちタイマーは既に5枚目。ここが半年後の生死を分ける」

リン（ゲームデザイン）
  「コアループが1本ではなく7本並列で走っている。閉じていない」

テツ（技術）
  「土台は思ったより頑丈。危ないのは保存とバックアップだけ」
```

**診断: 増築した機能が、本体（START）の前に立ち始めている。**

このアプリの本体は3行しかありません。

```text
   ジャンルを選ぶ  →  STARTを押す  →  25分たつ
                        ↑
        ここまでが「学習が続く」の全部。これより後ろは全部おまけ。
```

XP も オトモン も ギルド も 名言 も すごろくも、**STARTの「後ろ」にある限り無害**です。
危険なのは、それらがホーム画面に降りてきて START の前に立つ瞬間。それが今起きています。

## 2. 今日の最大の学び（次に同じ事故を起こさないために）

チームは「装備」と「響く言葉」を **繋ぎ忘れ** と報告しました。僕もそう判断し、
入口ボタンを復活させかけました。**両方とも間違いでした。**

```text
🎒 装備      … 画像が未完成で、アバターに重ねると絵が崩れる
              → 2026-07-03 に入口を撤去（81358c9）
              → 2026-07-08 に入手経路もオトモンへ置換（de40443）
              ＝ 2段階の計画的な引退

💬 響く言葉  … 一覧が「まだ出会っていない言葉」まで全部見せてしまい、
              ランダムで出会う楽しみを壊す作りだった
              → ヘッダー改修時に撤去
              ＝ 判断のある撤去
```

**コードから分かるのは「呼ばれていない」という事実だけで、「なぜ呼ばれていないのか」は分かりません。**
繋ぎ忘れと意図的な撤去は、見た目が完全に同じで、正反対の対応を要求します。

### 掟に8条目を追加することを提案

> **8. 機能を撤去したら、撤去したと記録する。**
> コードを消すだけでは「消し忘れ」と区別がつかず、将来の自分やAIが善意で復活させる。
> 撤去理由を、消した場所のコメントか `architecture_review.md` に1行残すこと。

今回は該当箇所（`index.html` のアバター操作ボタン群）にコメントとして記録済みです。

**チームへの指示にも反映すべき点**: 5人の担当は静的なコード読解しかできません。
「未使用」「到達不能」系の指摘は、**git履歴 → Obsidian Vault → ヨージに確認** の順で
意図を裏取りしてから提案する、という手順を必ず挟みます。

### フェーズ2 🔴 復帰した日に、迎える

**習慣化アプリの生死を分ける一点**（リンの評価）。ここは新機能ではなく「順番の入れ替え」です。

14日サボって開いたとき、アプリが自発的に発する最初の2つの情報：

```text
  ①  全画面モーダル「🔥 連続ログイン 1日目」   ← リセットの通知
  ②  ホームの数字  「🔥 連続日数 0」          ← 喪失の通知

  責めてはいない。記録も消えない。でも、迎えてもいない。
```

用意されている優しい言葉は**全部、自分から探しに行かないと見えません**。

| 出迎えの言葉 | 場所 | 自動で出るか |
|---|---|---|
| 妖精「おかえり。戻ってきたこと自体が、もう立派だよ」 | 🧚を押す | ❌ |
| ギルド「おかえり依頼」+15XP | 🏰を開く | ❌ |
| ナッジ「復帰の一手」+50XP | クエストカード | ⚠️ コース未選択なら出ない |
| 自信+5「戻ってきたことが、もう成長です」 | もう一度集中した後 | ⚠️ 遅すぎる |

**提案**: `data.streakWasBroken`（`quests.js:410` で既に正しく立っている）を使い、
復帰した日はログインボーナスのモーダルを**「おかえり」の画面に差し替える**。
新しいデータも新しい画面も要りません。**既にある部品の出す順番を変えるだけ**です。

### フェーズ3 🟠 報酬の重心を、学習に戻す

```text
■ 25分の集中               →  25 XP
■ アプリを開くだけ          →  最大 420 XP   （20 + min(streak,10)×10 ＋節目 +80/+300）

   ボタン1回が、25分の集中の 16.8倍
```

リンの試算では、続けているアカウントほど**学習が総XPに占める割合が約7%**まで落ちます。

| 提案 | 内容 |
|---|---|
| ログインXPを下げる | `20 + min(streak,10)×2` → 最大40。節目ボーナスは廃止 |
| 連続ログイン日数を廃止 | 学習streakと二重で走っており、復帰日に「0」と「1日目」を同じ画面で出している原因 |
| **演出はそのまま残す** | きらめきも🧚吸い込みも無罪。悪いのは数値だけ |

### フェーズ4 🟡 ホームの整理（三層モデル）

ホームは最大14枚のカード置き場になっています（index.html 10枚＋otomon.js 3枚＋バナー1枚）。
**14枚あること自体ではなく、14枚が全部フラットに縦積みで優先度の差が視覚的にゼロ**なのが問題です。

```text
【いま】フラット14層              【提案】3つの階層

  はじめの一歩                    ┌──────────────────┐
  今日のクエスト                  │ 🎯 いま            │ ← タイマー(START)
  🥚卵 / ⚡クエスト / 🤝お供      │                    │   常に最上段
  使命                            ├──────────────────┤
  今日の予定                      │ 📋 きょう          │ ← クエスト/予定/打刻
  ジャンル                        │                    │   をタブで1枚に
  ⏱ タイマー ★本命 ← 5枚目       ├──────────────────┤
  統計                            │ 📚 ふりかえり      │ ← 統計/カレンダー
  打刻                            │                    │   いちばん下
  カレンダー                      └──────────────────┘
```

あわせて見つかっている実バグ：
- 並べ替えの `KNOWN_IDS`（`boot.js:1238-1240`）に、既に存在しない `xp-panel` `mode-panel` の幽霊エントリが残っている
- otomonの3枚は `.widget` クラスを持たず並べ替え対象外。一度並べ替えると3枚だけ取り残される
- ヘッダー8ボタンが375px端末で1つ約31pxまで潰れる
- ロック中ナビのコントラストが **2.05:1**（AA基準は4.5:1）、しかも8px

## 4. ヨージにしか答えられない2つの問い

チームは全員ここで判定を保留しました。**コードには答えが無く、ヨージのデータにしか無い**からです。

### 問い1: このアプリは「学習ツール」か「制作物」か

カイの削減提案は、全部この答え次第で意味が反転します。

```text
学習ツールなら  → 機能が多いことは欠点。削るべき
制作物なら      → 機能が多いことは成果。削る理由がない
```

判定材料もカイが示しています。**`gq_data.history` の月別合計**——
機能を足した月に、学習時間は伸びたのか減ったのか。それが唯一の証拠です。

### 問い2: 名言に「♡」を何回押したか

`gq_words_favs` の件数を見るだけで決まります。**5未満なら、名言は削ってよい機能**（リン・カイ共通の基準）。
いまは♡を押しても見る手段が無い状態なので、どちらにせよ決着が必要です。
