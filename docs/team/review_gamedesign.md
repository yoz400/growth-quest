## 1. 総評（3行）

1. **コアループそのものは正しい。**「集中する → 妖精に一言答える → 世界樹に実がなる」という
   “学びの言葉が資産になる”回路は、習慣化アプリとして本当に良い設計です。ここは絶対に壊さないでください。
2. **ただし報酬の重心が学習から完全にズレています。** アプリを開くだけで最大 **420 XP**、
   25分集中しても **25 XP**。学習がXP総量に占める割合は成熟アカウントで **約7%** です。
   これは行動科学でいう**アンダーマイニング効果**（＝外からのごほうびが「やりたい気持ち」を食い潰す現象）の典型形です。
3. **「開くものが無くなる日」は4日目に来ます。** 段階解放（UNLOCK_DEFS）7件のうち、
   実際にUIボタンがあるのは4件だけで、その全部が最初の2〜4日で開き切ります。
   さらに**装備30種は入手経路が1本も無く、画面を開く導線すら存在しません**（詳細は §4-A）。

## 2. コアループ図と診断

### 2-1. 意図されている（美しい）ループ

```text
        ┌──────────────────────────────────────────┐
        │                                          │
        ▼                                          │
   ⏱ 集中する ──▶ 🧚 妖精が「何を知れた？」と聞く    │
                        │                          │
                        ▼                          │
                  🌳 世界樹に実がなる               │
                （自分の言葉が資産になる）           │
                        │                          │
                        ▼                          │
              「明日もこの木を育てたい」────────────┘
```

これが Growth Quest の心臓です。**報酬が「もらう物」ではなく「自分が書いた言葉」**である点が、
市販の学習アプリより圧倒的に強い。3年続く土台はここにしかありません。

### 診断

| # | 所見 | 深刻度 |
|---|------|--------|
| D1 | **ループが1本ではなく「並列に7本」走っている。** 学習ループ／ログインループ／ギルドループ／ナッジループ／すごろくループ／オトモンループ／誓いループが互いに接続されていない。どれか1本だけやっても報酬が出るので、**学習ループを飛ばしても成立してしまう** | 🔴 最重要 |
| D2 | **報酬の順番が逆。** 一番大きい報酬（ログインボーナス）を、一番努力していない瞬間（起動直後）に配っている。行動科学では報酬は「望ましい行動の**直後**」でなければ行動を強化しません | 🔴 |
| D3 | **セッション後の演出が渋滞している。** 自信トースト／クエスト達成トースト／バッジトースト／すごろく告／オトモン昇格トースト／アンロックトーストが、**`#confidence-toast` という単一のDOM要素を奪い合っている**。コードには `setTimeout(showPraiseSavedToast, gained ? 5600 : 1800)`（progression.js:332）のような**手作業の順番調整**が入っており、これは「報酬レイヤーが多すぎる」ことの物理的な証拠です | 🟠 |
| D4 | 良い点。`GQ.emit('session:complete')` が1箇所に集約されており、**ループを1本に束ね直す配線はすでに通っている**。改善の実装コストは低い | ✅ |

## 3. 数値分析

### 3-1. レベル曲線（`progression.js:66`）

```js
function xpForLevel(lv) { return lv * 100; }   // Lv N → N+1 に必要なXP
```

Lv1 から Lv L に到達するまでの累計XP = `50 × L × (L-1)`

| 区間 | 必要XP | **学習だけ**なら（1XP＝1分） | 実運用ペース（後述490XP/日）なら |
|------|--------|------------------------------|----------------------------------|
| Lv1 → Lv2 | 100 | 1時間40分 | 約0.2日 |
| **Lv1 → Lv10** | **4,500** | **75時間** | **約9日** |
| Lv10 → Lv20 | 14,500 | 242時間 | 約30日 |
| Lv20 → Lv35 | 40,500 | 675時間 | 約83日 |
| Lv35 → Lv50 | 63,000 | 1,050時間 | 約129日 |
| **Lv50 → Lv60** | **54,500** | **908時間** | **約111日** |

**Lv1→10 と Lv50→60 の比 = 12.1倍。** 曲線そのものは（線形増加なので）健全です。
問題は曲線ではなく、**分子に何が入っているか**です。

**軽量ユーザー（ログイン＋今日のクエスト＋1ポモドーロだけ）でも 37 ÷ 189 ＝ 約20%。**

> 🔍 **なぜこれが危険か（用語解説）**
> **アンダーマイニング効果**＝「もともと楽しくてやっていたことに、外からごほうびを付けると、
> かえってやる気が下がる」現象（Deci 1971）。
> GQ は今、**「学ぶこと」より「開くこと」に高い値札を付けている**状態です。
> 脳は素直なので、半年後には「開いてタップして閉じる」だけの日が増えます。
> 見た目のグラフ（レベル・名声）は伸び続けるので、**壊れていることに気づけない**のが最も怖い点です。

### 3-3. 「30日目」に何が起きるか

`_loginBonusXP(30)` = 20 + 100 + **300** = **420 XP**。
これは学習に換算すると **7時間分**。「受け取る」を1回タップするだけで手に入ります。
同じ日に7時間勉強した人と、アプリを開いただけの人が、同じXPを得ます。

## 4. 課題と改善案（優先度順）

### 4-A. 🔴 最重要：装備システム30種が「到達不能」

**これはデザインの問題ではなくバグです。先に報告します。**

```text
① 装備を手に入れる唯一の関数 grantRandomEquipmentItem()（core.js:881）
   ↑ 呼んでいるのは boot.js:1140 の
     「🎲 テスト入手（確認用・あとで外せます）」ボタン ただ1箇所

② そのボタンは equipment-overlay（装備モーダル）の中にある（index.html:391）

③ openEquipmentModal()（boot.js:1129）を呼んでいるコードは **どこにも無い**
   （grep 済み。ヘッダーにも data-unlock="equipment" のボタンが存在しない）

   → 装備モーダルを開けない → テストボタンを押せない → 装備が手に入らない
   → UNLOCK_DEFS の equipment は永久に false
```

**巻き添えで死んでいるもの**

- 装備30種（`ITEM_MASTER`）とレアリティ演出・コレクションUI一式
- `getEquipmentStreakProtect()`（core.js:952）→ **常に null**
  = 連続記録の3段目の保険が**永久に不発**（§4-C に直結）
- `getEquipmentDiceBonus()` → 常に0
- `getEquippedEffectItem('motiv_style')` → 常に null
  = `MOTIV_STYLES` の4口調（賢者・英雄・朝活・そよ風／progression.js:120-153）が全部死んでいる
- `quote_bias` / `mood` 効果も同様

**推奨**: すごろくの**チェックポイントマス（10,20,…,90 の9マス、現状+15XPだけ）**を装備配布に充てる。
`core.js:1095-1098` に `grantRandomEquipmentItem()` を1行足すだけで、
「1ステージ進むごとに最大9個の装備に出会う」という**ちょうどいいペースの長期コレクション**が生まれます。
30種 ÷ 9個 ≒ 3.3ステージ ≒ 165セッション ≒ **半年分の解放ラダー**。
「開くものが無くなる日」問題への、最も安上がりな回答でもあります。

### 4-C. 連続日数（streak）と「守りの盾」の診断

**保険は3段構えの設計になっています**（`quests.js:430-471`）。

```text
 空いた日数 diffDays の判定
 ├ 1日 ────────────────▶ 継続（streak +1）
 ├ 盾で全部保護済み ───▶ 継続（streak +1）      ← 🛡 守りの盾
 ├ 2日 & 🧊あり ───────▶ フリーズ消費して継続   ← 🧊 月1個・最大3個
 ├ 2日 & 🧊なし ───────▶ 装備 streak_protect で救済 ← ❌ §4-A により永久不発
 └ 3日以上 ────────────▶ streak = 0 ／ streakWasBroken = true
```

**穴が4つあります。**

| # | 穴 | 根拠 |
|---|----|------|
| P1 | **🧊フリーズは「2日空き」でしか効かない。** 3日空けた瞬間、フリーズを3個持っていても問答無用で0 | `quests.js:447` の条件が `diffDays === 2` |
| P2 | **装備による保護は永久に発動しない**（§4-A） | `core.js:952` `getEquipmentStreakProtect()` が常に null |
| P3 | **盾は「事後」にしか使えない。** `getMissedDaysInWeek` が `date <= today` で絞るため、**これから休む日を先に守れない** | `core.js:318-322` |
| P4 | **盾は手に入るかどうかが運任せ。** すごろくの common 11種のうち1つ → 期待入手 = 2セル × 30%（アイテムマス率） × 1/11 ≒ **1セッションあたり5.5%＝約18セッションに1個** | `core.js:341, 356` |

**そして最大の問題**：
> **ユーザーは「自分が今、何枚の保険を持っているか」を休む前に知る手段がありません。**
> ホームに出ているのは `🧊×N`（`quests.js:406`）だけ。盾を持っているかは
> すごろく画面を開かないと分かりません。
> **損失回避（失うのが怖い気持ち）は、失う前に「守れる」と知っていて初めて安心に変わります。**
> 今の設計では、損失回避が**純粋な不安**としてだけ働いています。

**推奨（小）**: ホームの `stat-freeze` を「🧊×2 🛡×1」の**まもり表示**に拡張する。
**推奨（中）**: `diffDays === 2` を `diffDays <= 1 + freezeItems` に変え、フリーズを複数日消費できるようにする。

```text
       │  ログインボーナス +30 XP │
       └─────────────────────────┘

  ④ ホームの stats-strip
       🔥 連続日数 = 0                                     ← ★2つ目に目に入る数字

  ⑤ ヘッダーの一言（progression.js:154 setHeaderMotivation）
     → 年内通算日 % 14 の固定ローテ。復帰とは無関係。
       運が良ければ「できない日があってもいい。また始めればいい。」が出るが、これは偶然
```

**「おかえり」は、アプリからは一度も自動で出てきません。**
用意されている出迎えは、**すべてユーザーが自分から探しに行かないと見えない場所**にあります。

| 出迎えの仕掛け | 場所 | 自動で出るか |
|---------------|------|-------------|
| 🫶 妖精のお告げ「おかえり。戻ってきたこと自体が、もう立派だよ」（`features.js:438-442`） | 🧚ボタンを押す | ❌ 手動 |
| 🕊️ ギルド「おかえり依頼」+15XP・自信+3（`boot.js:2199,2324`） | 🏰ギルドを開く | ❌ 手動 |
| 🕯 ナッジ「復帰の一手」+50XP（`quests.js:155,177,294`） | ホームのクエストカード | ⚠️ **コース未選択なら出ない** |
| 💪 自信+5「戻ってきたことが、もう成長です」（`timer.js:292`） | **もう一度集中した後** | ⚠️ 遅すぎる |
| 名言 `scenes:['comeback']`（`settings-genre.js:645`） | 名言画面 | ❌ 手動 |

> 🔍 **評価**
> **責めてはいません。ここは良いです。** 罰も無いし、記録も消えません。
> ですが **迎えてもいません。** アプリが自発的に発する最初の2つの情報が
> 「連続ログイン**1日目**」と「連続日数**0**」＝**どちらも喪失の通知**です。
>
> 復帰したユーザーが最初の3秒で受け取るメッセージが「あなたは失いました」だと、
> **せっかく開いたその日に再離脱します。**
> 用意されている優しい言葉たちは全部、そこを乗り越えた人だけが見られる場所にあります。
> **これが習慣化アプリの生死を分ける、まさにその一点です。**

## 5. 「新機能を1つだけ足せるなら」

### 🕯 **明日の自分への手紙（if-thenバトン）**

**何をするか**

```text
 ①【今日の終わり】セッション完了 → 妖精モーダルの最後に1行だけ追加

    ┌──────────────────────────────────────┐
    │ 🧚 明日、どこから始める？             │
    │ ┌──────────────────────────────────┐ │
    │ │ 朝ごはんのあと、英単語を5個だけ  │ │
    │ └──────────────────────────────────┘ │
    │                        [ 明日へ渡す ] │
    └──────────────────────────────────────┘
                    │
                    │  gq_baton = { date, text }
                    ▼
 ②【明日の起動】ログインボーナスモーダルの一番上に、自分の字で返ってくる

    ┌──────────────────────────────────────┐
    │ 🕯 昨日のあなたから                   │
    │  「朝ごはんのあと、英単語を5個だけ」   │
    │                    [ よし、やる ] ──▶ タイマーへ直行
    └──────────────────────────────────────┘

 ③【14日サボって戻った日】同じ枠が、自動で出迎えに変わる

    ┌──────────────────────────────────────┐
    │ 🕯 14日前のあなたが、こう書いていました│
    │  「朝ごはんのあと、英単語を5個だけ」   │
    │                                        │
    │  ずっと、ここで待ってたよ。            │
    │  今日は1分でいい。                     │
    │                    [ 1分だけ戻る ] ──▶ タイマーへ直行
    └──────────────────────────────────────┘
```

**なぜ、これなのか（5つの理由が1機能に重なるから）**

| # | 効く理由 | 用語の意味 |
|---|---------|-----------|
| 1 | **実装意図（if-thenプランニング）**を作る | 「Xしたら、Yする」と**事前に文章で決めておく**手法。習慣化研究で最も効果量が大きい介入の1つ（Gollwitzer 1999）。「がんばる」より「朝ごはんのあと」の方が3倍実行される |
| 2 | **ピーク・エンドの法則**を正しく使う | 人は体験を「一番強かった瞬間」と「終わり方」で記憶する。今のGQの終わりは褒めログ入力で**開いたまま終わる**。「明日へ渡す」は終わりに閉じる感覚を作る |
| 3 | **翌日の起動理由を「報酬」から「約束」に置き換える** | XPで釣るのをやめても起動率が落ちない唯一の方法が、これ。§4-B の🔴2（ログインボーナス減額）を**安全に実行できるようになる** |
| 4 | **復帰体験が自動で出迎えに変わる**（§4-D の解決） | 新しいモーダルを作らず、既にある `login-bonus-overlay` の中身を差し替えるだけ。**必ず全画面で見る唯一の場所**を、喪失通知から出迎えに転換できる |
| 5 | **ループが1本に閉じる**（§2 D1 の解決） | 「集中 → 実がなる → **明日への一言** → 翌朝それを読む → 集中」。7本の並列ループの中で、**唯一 起動と学習を直結させる線**になる |

**実装コストが低い理由**

- 新規モーダル **0個**（既存の妖精モーダルとログインボーナスモーダルに各1ブロック追加）
- 新規localStorageキー **1個**（`gq_baton`）→ 掟§4-5の3点セット（台帳追記＋exportAllData）だけ守ればOK
- **既存機能と重複しない**: ナッジコース `habit` の「明日の自分へバトン」（`quests.js:173`）と発想が同じですが、
  あれは**コースを選んだ人にしか出ない・翌朝どこにも表示されない**ため機能していません。
  → **あの1項目を吸収して昇格させる形にすれば、報酬レイヤーは増えずに済みます**（むしろ1本減る）。

## 6. 今すぐ削るか統合すべき報酬レイヤー

現状、報酬レイヤーは **19本** あります。
（XP／自信／バッジ／すごろく位置／すごろくアイテム／装備／オトモン／なつき度／ふれあいstreak／
ギルド名声／ギルド依頼ランク／学習streak／🧊フリーズ／ログインstreak／世界樹の実／誓いの祠／
今日のクエスト／選択肢クエスト／アバター進化）

### 🥇 第1位：**ログインボーナスのXPと「連続ログイン日数」を削る**（必須）

| 項目 | 現状 | 提案 |
|------|------|------|
| ログインXP | `20 + min(streak,10)×10` ＋節目 → **最大420** | `20 + min(streak,10)×2` → **最大40**（節目ボーナスは廃止） |
| 連続ログイン日数 `gq_login_streak` | 学習streakとは**別カウント**。開くだけで伸びる | **廃止**。表示は学習streakに一本化 |
| 全画面モーダルの演出・きらめき・🧚吸い込み | 良い | **そのまま残す**（§5 のバトン置き場になる） |

**理由（3つとも同じ結論を指しています）**

1. **アンダーマイニング効果**：25分の集中が25XP、開くだけが最大420XP。
   この比率のまま3年走らせると、「学習しなくてもレベルが上がる」ことを脳が学習します。
2. **連続が2種類あると、どちらも意味を失う**。
   `data.streak`（学習）と `gq_login_streak`（起動）が別々に走っており、
   14日サボって戻った日にホームは「0」、モーダルは「1日目」と、**同じ画面で違う数字を出しています**。
3. **演出は無罪**。悪いのは数値だけです。演出を残したままXPを下げれば、
   ユーザー体験の華やかさは1ミリも損なわれません。

### 🥈 第2位：**誓いの祠のXPを削る**

`fulfillVow()`（`boot.js:2032-2044`）は、自分で書いた誓いに自分で「✓ 果たした」を押すだけで
**+50XP／+自信5／+名声50** が無制限に入ります。
→ **XPと名声を外し、祝福演出（`showVowBlessing`）と「🏆 成就した誓い」の記録だけ残す**。
祠の価値は数値ではなく**記録が石碑として残ること**にあります。数値を外した方が、むしろ神聖になります。

### 🥉 第3位：**バッジ137種のうち「自動で埋まる28種」を隔離**

曜日7種＋月12種＋時刻9種＝**28種**は、学習の質・量と無関係にカレンダーが進めば埋まります
（`settings-genre.js:1219-1237`）。
→ **「記録」タブに分離し、獲得トーストを出さない。**
価値の低い通知が混ざると、**本当に価値のあるバッジ（100日連続・累計200時間）まで無視されるようになります**。

### 補足：統合の余地

| 統合案 | 内容 |
|--------|------|
| **自信ゲージ → XPへ吸収を検討** | `addConfidence` は8箇所から呼ばれるが、100たまると「自信Lv」が1上がるだけで、**ゲームメカニクスに一切影響しない**（バッジ条件を除く）。XPと役割が完全に重複している。残すなら「XPは量、自信は行動の多様性」のように**軸を明確に分ける**こと |
| **ふれあいstreak → 学習streakへ統合** | オトモン個体ごとの `rec.streak`（`otomon.js:894`）は、GQ全体で**3本目の「連続」**。3本は多すぎる |

## 付録：ヨージへの3行まとめ

1. **まず §4-A の装備バグを直してください。** 30種のアイテムと連続記録の保険1本が、
   今まるごと死んでいます。すごろくのチェックポイントに1行足すだけで、半年分の解放ラダーが生まれます。
2. **次にログインボーナスのXPを 420 → 40 に下げてください。** 演出はそのままで大丈夫です。
   これをやらないと、どんな機能を足しても「開くだけでレベルが上がるアプリ」のままです。
3. **最後に §5 の「明日の自分への手紙」を足してください。** これ1つで、
   復帰体験・終わりの余韻・翌日の起動理由・バラバラな7本のループが、まとめて1本につながります。
