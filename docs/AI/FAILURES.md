## 2026-08-23 — 4体並べたのに1体しか見えない（同じ軌道に完全に重なっていた）

### 事象

完璧な週で走る相棒を1体→最大4体に増やしたが、画面には1体しか居ないように見えた。
DOM には4体ちゃんと居て、画像も4種類とも読めていた。原因は全員が同じ
`@keyframes pwMove`（left 4%→88%）に乗り、同じ高さ・同じ速さで走っていたこと。
ぴったり重なると、要素が増えても見た目は1体のまま。

さらに検証中のブラウザが `prefers-reduced-motion: reduce` だったため、
app.css 末尾の全体ルール（`animation-duration: .01ms !important`）で動きが
潰され、4体が同じ座標に固まっていた。**アニメで散らす設計は、アニメを切って
いる人には効かない。**

### なぜ気づけなかったか

「要素が4つ生成されているか」を DOM で確認して満足した。
数が合っていても、座標が同じなら見え方は1つ。**目視のスクショを撮るまで
「増えた」と判断してはいけない。**

### 再発防止（ルール）

同じ animation を複数要素に付けるときは、必ず次の2つをセットで散らす:

1. **動いているときの軌道** … keyframes の値を CSS 変数にして
   （例 `left: var(--pw-from, 4%)`）、要素ごとに JS から別の値を渡す
2. **止まっているときの位置** … inline style で `left` 等を要素ごとにずらす。
   `prefers-reduced-motion` ではアニメが即終了し、fill-mode が無ければ
   非アニメ時のスタイルに戻るので、ここが最終的な見た目になる

検証は DOM の個数ではなく、**スクリーンショットで実際に散っていること**を見る。

## 2026-08-23 — 「タップしても反応しない」は、実装バグではなく無反応セルだった

### 事象

「オトモン図鑑のセルをタップしても何も起きない」とバグ報告を受けた。
調査した結果、**コードの配線は全て正常**だった。ヨージが押していたのは
未発見（？？？）のセルで、そこには最初から click リスナーが無かった。

### 原因

未発見セルは `data-otomon` を持たず、リスナーの対象外。
そして押しても**何の反応も返さない**（メッセージも見た目の変化も無い）。
100マス中95マスが無反応マスだったため、適当に押せばほぼ確実にそちらに当たる。

**ユーザーには「仕様で押せない」と「壊れて押せない」が区別できなかった。**

### 兆候

「開くけど中が効かない」という報告は、
**実装の断線ではなく "そこは元々押せない" の可能性**を先に疑う。
再現環境で普通に動いてしまったら、まずユーザーの操作対象を特定する。

### 再発防止

- **仕様**: 押せない要素は必ず「押せない理由」を返す（無言で沈黙させない）。
  図鑑の未発見セルは「まだ会っていないオトモンだよ」を表示するようにした（guild-160）
- **切り分け手順**: 実機バグ報告は
  ①コンソール不要で目視できる質問に落とす（件数・文言の有無・見た目）
  ②再現環境で動いたら「押した対象」を図で確認する
  この2段でヨージへ聞く。今回は「？？？のマスと絵入りのマス、どちらを押したか」で確定した

## guild-141 — 本番が起動不能になった（読み込み時参照 / TDZ）

### 事象

本番環境でアプリが起動しなくなった。しかも全員ではなく
**「ナッジコースを選んでいる人」にだけ**発生した。

### 原因

前に読み込まれるファイルから、後に読み込まれるファイルの関数を
「読み込み時点で裸で」呼んでいた。

function宣言の巻き上げはファイル内でしか効かない。
let/const は TDZ（宣言行より前で触るとエラーになる期間）があるため、
`typeof` によるガードも効かない。

### 兆候

- 同種の事故は**これで3回目**だった
- 3回とも**目視レビューでは発見できなかった**
- `localStorage.clear()` から始めるプレビュー検証では**一度も再現しなかった**

### 再発防止

- `tools/check_load_order.py` を作成。JSを編集したら必ず実行する（数秒）
- コールバックは必ず `() => fn()` で包む
- **条件付きで走る経路は、条件を作らないと踏めない。**
  プレビューでの正常動作は「検証した」ことにならない
- CLAUDE.md / AGENTS.md の「開発の掟」2番に明記済み

## 「直したのに直ってない」 — キャッシュバスターの更新漏れ

### 事象

CSS / JS を修正しても、ブラウザに変更が反映されない。
「さっき直したはず」の症状が続き、原因究明に時間を溶かす。過去に何度も発生。

### 原因

`?v=guild-N` のキャッシュバスターを更新していないため、
ブラウザが前回のファイルを使い回していた。

### 兆候

コードは明らかに直っているのに、画面だけが古い。

### 再発防止

- `bash tools/bump_version.sh` で一括+1する
- CSS/JS を編集したら**必ず**実行。CLAUDE.md / AGENTS.md の掟1に明記済み
