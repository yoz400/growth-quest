# AI運用の全体像

> **1枚で把握するための索引。** 詳細は各ファイルへ。
> 更新日: 2026-08-08

## 何のための仕組みか

**AIが変わっても、ヨージの知識・目標・決定が消えないようにするため。**

チャット履歴は検索できないし、移行できないし、いつか消える。
だから長く残すものは AI の中ではなく `docs/AI/` に置く。
AIは入れ替え可能な実行エンジンとして扱う。

残すのは「何を話したか」ではなく **「何を決めたか」**。

## 基本の流れ

```text
    ヨージ
      │  目的・優先順位を決める
      ▼
  ChatGPT ──── 何を作るか / なぜ作るか
      │
      ▼
  docs/AI/ ◀──────────────────┐
  （記録の置き場）              │
      │                        │
      ▼                        │
    クロ ──── 調べる・設計する・仕様書を書く
      │                        │
      ▼                        │
   Codex ──── 仕様書どおりに実装する
      │                        │
      ▼                        │
  確かめる ── スクリプト → クロが差分レビュー
      │                        │
      └────── 記録を戻す ──────┘
```

## 誰が何をするか

| 担当 | 仕事 | なぜそこか |
|---|---|---|
| **ChatGPT** | 企画・優先順位・文言・仕様の妥当性チェック | コードを読む必要がない仕事。ここが一番安い |
| **クロ** | 調査・設計・仕様書作成・差分レビュー・小さな修正 | コードを読める。ここが一番高いので設計に集中 |
| **Codex** | 仕様書ベースの実装 | 仕様書経由なら、コード全体を読まずに済む |
| **スクリプト** | check_load_order.py などの機械チェック | トークンを一切使わない。一番強い |
| **ヨージ** | 最終判断・CONTEXT の中身 | ここだけは自動化できない |

## ファイルの役割

| ファイル | 中身 | いつ読む |
|---|---|---|
| `CURRENT.md` | 今どこにいるか（60行以内） | **毎回** |
| `CONTEXT.md` | どこへ向かうか・理想・役割表 | 目的が不明なとき |
| `DECISIONS.md` | 決めたことと理由 | 「なぜこうなってる?」と思ったとき |
| `FAILURES.md` | 過去の事故と再発防止 | 同じ種類の作業に入る前 |
| `INSTRUCTIONS.md` | 依頼・報告のひな形 | 依頼を書くとき |

実際の作業ルールは `CLAUDE.md`（クロ用）と `AGENTS.md`（Codex用）にある。

## 迷ったときの3つのルール

1. **記録していない作業は、完了していない**
2. **全部読まない。** コード約333k＋docs約184kトークンで、全体を読めるAIは存在しない
3. **受け入れ基準のない依頼は、作業前に確認する**

## 目的別インデックス

| したいこと | 見る場所 |
|---|---|
| 今なにをすべきか知りたい | `CURRENT.md` |
| この機能を作るべきか迷う | `CONTEXT.md` の「理想」3フェーズ |
| なぜこの仕様なのか知りたい | `DECISIONS.md` |
| 同じ失敗を避けたい | `FAILURES.md` |
| クロに依頼を書きたい | `INSTRUCTIONS.md` §3 |
| 自分でやるか Codex に渡すか迷う | `INSTRUCTIONS.md` §1（50行が分かれ目） |
| ChatGPT に何を頼めるか知りたい | `INSTRUCTIONS.md` §2 |
| レビューのやり方 | `INSTRUCTIONS.md` §5（差分だけ見る） |
| 設計の正典を読みたい | `../architecture_review.md` |

## この仕組みが生きているかの目安

- `CURRENT.md` の更新日が3日以内か
- `DECISIONS.md` に月3件以上の追記があるか
- レビューで実際に指摘が出ているか（0件が続くなら形骸化）
- `FAILURES.md` に記録があるか（0件は「失敗していない」ではなく「記録していない」）
