## 1. H-1：並べ替えがカードを置き去りにする（最優先・バグ修正）

### 何が起きるか

ウィジェットの並べ替えは `.widget` クラスの付いた**7枚だけ**を対象にしている
（[boot.js:1243](../scripts/boot.js:1243) `getWidgets()`）。ホームにはそれ以外にも
カードがあり、**並べ替えるとその相対位置が壊れる**。

```text
【並べ替え前】                    【timer を先頭にして再訪したあと】
  ジャンル                          はじめの一歩      ← 置き去り
  ⏱ タイマー                        今日の予定        ← 置き去り
  はじめの一歩                      ⏱ タイマー        ← ユーザーが先頭にしたはず
  今日のクエスト                    ジャンル
  🥚卵 / 🤝お供 / ⚡クエスト        今日のクエスト
  使命                              🥚卵 / 🤝お供 / ⚡クエスト
  今日の予定                        使命
  統計 / 打刻 / カレンダー          統計 / 打刻 / カレンダー
```

原因は `applyOrder` が **既知の7枚を `app.appendChild()` で末尾へ送り直す**方式だから
（[boot.js:1274-1277](../scripts/boot.js:1274)）。対象外のカードはその場に残るので、
結果として**全部の上に浮き上がる**。

### なぜ重大か

**ロードマップ フェーズ1-1「STARTを画面内へ」を打ち消す**。
ユーザーがタイマーを先頭に持ってきても、対象外カードが上に割り込む。

実測（375x812・並べ替え後・両カードが表示状態のとき）:

```text
はじめの一歩   上端 192px
今日の予定     上端 351px
⏱ タイマー     上端 432px   ← 先頭にしたのに3番目
START          上端 703px   （画面の高さ 812px）
```

### 対象外になっているカード（全5枚）

| id | 出どころ | クラス |
|---|---|---|
| `onboard-card` | [index.html:168](../index.html:168) | `glass`（`widget` 無し） |
| `today-plan-card` | 手帳S3-2が生成 | `glass` |
| `otomon-egg-card` | [otomon.js:1228](../scripts/otomon.js:1228) | `glass` |
| `otomon-buddy-card` | [otomon.js:1466](../scripts/otomon.js:1466) | `glass` |
| `otomon-quest-card` | [otomon.js:1533](../scripts/otomon.js:1533) | `glass` |

### 直し方（2案。**A案を推奨**）

**A案：並べ替えを「動かさないカード」に配慮する形へ変える**

`applyOrder` を「末尾へ送り直す」から「**既知ウィジェットの並びだけを入れ替える**」に変える。
対象外カードは**元の位置（DOM上の前後関係）を保つ**。

```javascript
// 変更前：既知の7枚を末尾へ送り直す＝対象外カードが上に取り残される
for (const id of orderedIds) {
  const el = document.getElementById(id);
  if (el) app.appendChild(el);
}

// 変更後：いま .widget が占めている「席」だけを並べ替える。
//         対象外カードの位置は動かさないので、上に浮き上がらない。
const slots = getWidgets();                        // いまの .widget の出現位置＝席
const cards = orderedIds.map(id => document.getElementById(id)).filter(Boolean);
slots.forEach((slot, i) => {
  if (cards[i] && cards[i] !== slot) app.insertBefore(cards[i], slot);
});
```

> ⚠️ 席の数とカードの数がズレる場合（未解放で非表示のカードなど）に備え、
> `slots.length !== cards.length` のときは**並べ替えを諦めてデフォルト順のままにする**。
> 中途半端に動かすほうが壊れて見える。

**B案：対象外カードにも `widget` クラスを付けて並べ替え対象にする**

一見きれいだが、**採用しない**。理由は3つ:
- `onboard-card` は「はじめの一歩」で、**新規ユーザーにだけ出て自動で消える**。
  並べ替えの対象にすると「消えたカードの席」が保存に残る
- otomonの3枚は `daily-quest-card` の直後に置くことに意味がある（クエストと並べて見せる設計）
- 保存キー `gq_widget_order` の中身が変わるので、**既存ユーザーの並びが1回壊れる**

### H-1 の受け入れ基準

- [x] タイマーを先頭に並べ替えて**リロードしても**、タイマーがいちばん上にある
- [x] `はじめの一歩` `今日の予定` `オトモン3枚` が、並べ替え後もそれぞれ元の前後関係を保つ
      （オトモン3枚は `今日のクエスト` の直後のまま）
- [x] 並べ替えのリセットボタンでデフォルト順に戻る
- [x] 375px で START が初回表示の画面内（上端 812px 以内）に収まる
- [x] コンソールエラーゼロ／`bash tools/bump_version.sh` 実行済み
- [x] ドラッグ操作そのものが壊れていない（§5 の懸念）

## 2. H-2：ヘッダーの操作性（8ボタン）

### 実測（375x812）

```text
ボタン8個  幅34px × 高40px       ← 推奨は44x44
ロック中のラベル  2.16 : 1        ← AA基準は4.5 : 1
ロック中の文字     7.68px          ← 小さすぎて読めない
解放済みのラベル  5.45 : 1        ← こちらは基準を満たしている
```

ロック中が読めないのは**二重に薄くしているから**。
ボタン全体に `opacity: .5`、その中のラベルに `rgba(255,255,255,.48)`
（[app.css:4177-4186](../styles/app.css:4177)）→ 実効 0.24。

### 🚨 この節の初版は2か所間違っていた（2026-08-04 訂正）

Codexが §5 の停止条件（「44pxにしたら320pxで折り返す」）に該当するとして
実装せず報告してきた。**その判断は正しく、間違っていたのは仕様書のほうだった。**

**間違い①：計算ミス**

「8個 × 44px = 352px。375px 端末なら収まる」と書いたが、ヘッダー右側で実際に
使える幅は **375px端末で313px / 320px端末で270px**（ロゴとアバターを除いた残り）。
44pxで置ける個数は **375pxで6個・320pxで5個**であり、8個は最初から入らない。

**間違い②：44px は達成すべき基準ではなかった**

```text
WCAG 2.5.8 Target Size (Minimum) — レベルAA   24 x 24 px  ← 現状32x35で既に満たしている
WCAG 2.5.5 Target Size (Enhanced) — レベルAAA  44 x 44 px  ← Apple推奨と同値。私が持ち込んだ
```

**現状でもAAは満たしていた。** 8個では物理的に不可能な上位基準を、根拠なく
要件に書いてしまっていた。「44pxのために機能を減らす」という検討自体が不要だった。

### 直し方（改訂版）

**横に広げるのではなく、ラベルを2行に折り返して縦で稼ぐ。** 8個すべて残せる。

1. **二重の薄さをやめる**。`opacity: .5` を外す。ラベル色にも掛かって実効0.24になっていた
2. **文字を 10px 以上に**。`font-size: max(10px, .5rem)` とし、
   段階的に縮めていた4つのブレークポイント指定（`.48rem` `.45rem` `.35rem`）を撤去する
3. **1行固定をやめる**。`white-space: nowrap` → `normal`。日本語は既定でどこでも
   折り返せるので `word-break` は不要。切り落とし（`overflow: hidden`）も外す
4. **2行ぶんの高さを確保**。各ブレークポイントの `min-height` を 48px に揃える

> ⚠️ **ロック中と解放済みの差を「濃さ」で付けようとしないこと。**
> 実際に試すと、ロック中を4.5:1まで上げた時点で **9.82:1 になり、
> 解放済み（5.45:1）より目立つ**という逆転が起きた。
> 「読める濃さ」と「見分けが付く濃さ」は両立しない。
> **両方とも同じ濃さで読めるようにし**、ロック中であることは既存の2つで伝える:
> ラベルが「？？？」（機能名が出ない）／絵文字が `grayscale(1) brightness(.45)`。

### H-2 の受け入れ基準（改訂版）

- [x] ラベルのコントラストが **4.5 : 1 以上**（測って数値を報告すること）
- [x] ラベルの文字が **10px 以上**
- [x] タップ領域が **24 x 24px 以上**（WCAG 2.5.8 AA）。44x44 は要求しない（上記の訂正）
- [x] 320px 幅でもヘッダーが横スクロールしない
- [x] ラベルが切り落とされない（折り返して全文が見える）
- [x] ロック中と解放済みが一目で見分けられる
- [x] 機能を1つも隠していない
- [x] コンソールエラーゼロ／`bump_version.sh` 実行済み

## 3. H-3：三層化（⚠️ ヨージの判断が要る。まだ着手しない）

ロードマップの本題。ホームの最大14枚を「いま／きょう／ふりかえり」の3層にまとめる案。

```text
【いま】フラット14層          【提案】3層
  …14枚が縦に並ぶ               🎯 いま        ← タイマー（常に最上段）
  優先度の差が視覚的にゼロ      📋 きょう      ← クエスト/予定/打刻をタブで1枚に
                                📚 ふりかえり  ← 統計/カレンダー
```

**これは仕様書だけでは決められない。** 理由は、3層に畳むと
**いくつかのカードがタブの裏に隠れる**からで、どれを隠してよいかはヨージにしか分からない。

### ヨージに決めてもらうこと

1. **「きょう」タブに何を入れるか**（クエスト／今日の予定／打刻／使命／オトモン3枚）
2. **タブを開いた状態を覚えるか**（覚えると「いつも同じタブしか見ない」が起きる）
3. **並べ替え機能をどうするか** — 3層にすると自由な並べ替えと矛盾する。
   層の中だけ並べ替え可にするか、機能ごと畳むか

### 先に測るとよいこと（判断材料）

「どのカードが実際に見られているか」はデータが無いと分からない。
H-1・H-2 を出したあと、**1〜2週間ふつうに使ってから**決めるのが確実だと思う。

   ```javascript
   (() => {
     const parse = c => c.match(/[\d.]+/g).map(Number);
     const over = (fg, bg) => { const a = fg[3] ?? 1; return [0,1,2].map(i => fg[i]*a + bg[i]*(1-a)); };
     const lum = c => { const s = c.map(v => { v/=255; return v<=.03928 ? v/12.92 : ((v+.055)/1.055)**2.4; });
                        return .2126*s[0] + .7152*s[1] + .0722*s[2]; };
     const ratio = (a,b) => { const [x,y] = [lum(a),lum(b)].sort((p,q)=>q-p); return (x+.05)/(y+.05); };
     const page   = parse(getComputedStyle(document.body).backgroundColor).slice(0,3);

     const locked = document.querySelector('.header-right .feat-locked');
     const label  = locked.querySelector('.icon-btn-label');
     const btnOp  = Number(getComputedStyle(locked).opacity);      // ボタン側の薄さも掛ける
     const raw    = parse(getComputedStyle(label).color);
     const eff    = over([raw[0],raw[1],raw[2], (raw[3] ?? 1) * btnOp], header);
     const r = locked.getBoundingClientRect();
     return {
       コントラスト: ratio(eff, header).toFixed(2) + ' : 1',
       文字サイズ: getComputedStyle(label).fontSize,
       タップ領域: Math.round(r.width) + ' x ' + Math.round(r.height) + ' px',
     };
   })()
   ```

## 7. 実装記録

### ✅ H-1 完了（2026-08-03 クロが実装・検証）

Codexではなくクロが直接実装した（ヨージの指示）。`?v=guild-135`。

**§1 の A案には穴が2つあった。実装しながら見つけて塞いだ。**

**穴①：素朴な `insertBefore` では順序が壊れる**

仕様書に書いた擬似コードは、席を順に見て `insertBefore(cards[i], slots[i])` するものだった。
これは**動かした要素がそれ以降の席の位置をずらす**ため、正しい順序にならない。

```text
A B C を C A B にしたい場合
  i=0: C を A の前へ  → C A B
  i=1: A を B の前へ  → C A B（変化なし）
  i=2: B を C の前へ  → B C A   ✗ 期待と違う
```

席にいったんコメントノードの目印を置き、目印を頼りに差し込む形へ変更した。

**穴②：席を入れ替えるとオトモンがクエストから離れる**

席は「位置」であって「どのカードの隣か」ではない。`daily-quest-card` が別の席へ動くと、
オトモン3枚は元の位置に取り残される。**受け入れ基準の2つ目を自分で満たせていなかった。**

`data-follows="daily-quest-card"` を3枚に付け、並べ替えの後に
アンカーの直後へ戻す `reattachFollowers()` を追加した。ドラッグ完了時にも呼ぶ
（クエストを手で動かしたときにも追従させるため）。

**検証**

ロジックは jsc で7項目（末尾を先頭へ／先頭を末尾へ／非widgetが浮き上がらない／
オトモンが追従する／3枚どうしの順序も保たれる／数が合わないときは諦める／冪等）。
実機（375x812）では以下を確認した。**普段非表示のカードは強制表示してから測っている。**
